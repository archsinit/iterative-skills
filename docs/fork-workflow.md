# Focused fork adaptation

This fork preserves Matt Pocock's MIT-licensed skill set and historical attribution while changing one workflow:

| Upstream | This fork |
| --- | --- |
| `grill-with-docs` | `grill-the-basics`: end product and overall success, facts owned by the agent, consequential decisions only |
| `to-spec` | Required tracked product-agreement and execution-envelope handoff |
| `to-tickets` | Deprecated archive, excluded from promoted indexes/plugin |
| `implement-spec` | `implement-loop`: bounded numbered runnable slices, real-surface evidence and local commits |
| `ask-matt` | Adopted router name `ask-the-playbook` |

The active route is **basics -> spec -> loop**. Do not infer the old ticket graph or optional-spec route from retained upstream prose. Basics defines the desired end product, not a detailed feature list or roadmap. Spec persists the product agreement and execution envelope without requiring a selected first slice. The loop chooses and precisely defines usable slices toward that outcome as evidence accumulates; no new dependencies, schedulers or pstack imitation are involved. Host instructions and explicit permissions always win.

A latest verified runnable checkpoint is preserved separately from a changing candidate. See [checkpoint mechanics](../skills/engineering/implement-loop/CHECKPOINTS.md). Failed/incomplete iteration commits say NOT runnable; acceptance belongs to the human, not tests. A human-selected earlier checkpoint starts a new branch and the same three-step route with a versioned spec and explicit redirected authority.

## Retained material

Unrelated skill instructions and their upstream docs remain intact except direct fork cross-reference notices. Their own standalone workflows still apply. Targeted supporting compatibility edits make TDD seams agent-owned within authorised outcomes, make code-review local-spec-first with current uncommitted scope and permitted background/self-review modes, and bound optional retro access.

Each loop reviews its current slice on Spec and Standards plus runtime verification before a working checkpoint commit. Consequential changes use proportionate independent review where available. At run end a cumulative review from the fixed starting checkpoint catches integration/cross-slice drift. These reviews are built in; explicit code-review and user-invoked retro remain optional additional scrutiny and environment learning, not mandatory human gates. References to old build sequencing inside those docs describe the upstream context, not a recommendation for this fork. The fork router is the current map. Archived removed-skill pages and CHANGELOG/ADRs preserve historical names and releases deliberately.

New/changed fork docs link to this repository rather than claiming unpublished pages exist on aihero.dev. The upstream official marketplace does not ship this fork. Installation examples select `archsinit/iterative-skills` and `iterative-skills@archsinit`; runtime installation/update behavior is unverified here.
